# Generated landing pages and labels

## Ownership

The personal pages and subscription labels are generated by the central live
script. The live `HTML_TEMPLATE` / title mapping is the durable edit point.
Generated files under `nnect/` and `sub/` are outputs and will be overwritten
by `sync` or `webfix`.

## Safe page-release workflow

1. Fetch/stage the current live generator and identify the active template;
   legacy templates may exist in the same source.
2. Compare it with local ideas. Do not overwrite live with an older local
   `autoXRAY_davida_custom.sh` without comparison.
3. Create a dated backup of the live source and affected generated output.
4. Apply the smallest source-level template/mapping change.
5. Check shell syntax before executing the generator.
6. Run the narrow supported refresh (`webfix` only after identifying its domain
   scope; `sync` only if subscription generation must change).
7. Test a personal page at desktop and mobile widths, interactions, browser
   console, and an HTTP 200 response.

## Design boundaries

Personal pages may be visually rich, but must preserve the primary actions:
download HAPP and add/open the user's subscription. Visual work must not alter
the subscription engine, server connection data, or HAPP profile schema.

The current client compatibility baseline avoids custom HAPP metadata and fake
profiles. Keep labels as ordinary profile remarks where possible. A page-only
design can be deployed independently from a subscription format change.

Current profile remarks are maintained in the central catalog, not in the page
template: Switzerland is `тест`, Finland and Estonia are `норм`, and Germany
is `запас`. For a label-only change, back up the central catalog, apply a
validated JSON transformation to that source, run `sync <domain>`, and verify
every generated user file. Never hand-edit an individual user's JSON.

## Local previews

Workspace preview files (including aurora/reference variants) are drafts until
the source-level release workflow above is completed. Do not call a local
preview “deployed” merely because it is open at `127.0.0.1`.
